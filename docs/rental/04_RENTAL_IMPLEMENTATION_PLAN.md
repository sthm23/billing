## Фаза 6. Mobile (billing-mobile)

Источник UI — дизайн STHM (claude.ai artifact `LBqDuZU3wDgKNJXJBfrAYb`, страницы «Аренда · список / бронь / карточка / возврат / товар и настройки»). Распределение скидки — тот же алгоритм, что в web (`docs/features/rental.md#set-discount-distribution`).

Решения (2026-11-06):
- Режим магазина: только аренда — вкладка «Заказы» становится «Аренды», центральная кнопка создаёт бронь; продажа + аренда — меню переключается в Профиле («Режим: продажа или аренда», локальная настройка).
- Просрочка: штраф по-прежнему вручную (R4). Сервер в preview возврата отдаёт дни просрочки и сумму по тарифу; поле «Штраф» предзаполняется ею, продавец может изменить или обнулить.
- Номер брони — короткий код из id (без миграции), поиск по нему.
- Новые поля: «выдано без залога» у брони (с сотрудником — `issuedBy` уже есть); химчистка по умолчанию у варианта (подставляется при возврате).
- «Экземпляров» в форме товара — только показ, меняется через «Приход / Списание» (StockMovement).
- В объёме: календарь (месяц/неделя), карточка вещи с занятостью, «Похожие» в замене (та же категория, сдаётся, свободно на даты).

## Фаза 8. Химчистка вне возврата (R13, план 2026-11-07)

Дизайн: STHM, страница «Аренда · товар и настройки», макеты 13 (`CleaningNew`, `RentalProductCleaning`). Решения пользователя: без экземпляров (1 единица варианта), расход сразу в открытую кассу, конфликт с бронью запрещает сохранение, отмена до начала со сторно.

- **8.1 Backend — готово 2026-11-07.** Модель `RentalCleaning` + `RentalCleaningStatus`, категория `DRY_CLEANING`, миграция `20261107120000_rental_cleaning`. `findOccupancy` учитывает активные химчистки (`Occupancy.cleaningId`; `rentalId` может быть `null`). `RentalCleaningService`: `GET /rental/cleanings/check`, `GET /rental/cleanings`, `POST /rental/cleanings`, `POST /rental/cleanings/:id/cancel`. Календарь: `days[].cleaning`, `variants[].cleanings[]`; `bookings[]` — только брони. Тесты `rental-cleaning.service.spec.ts`.
- **8.2 Web (billing_ui) — готово 2026-11-09.** `DRY_CLEANING` в моделях и подписях кассы («Химчистка»; в ручную форму не добавлена). Карточки варианта аренды в web нет, поэтому всё — в календаре занятости: кнопка «В химчистку» у варианта → `rental-cleaning-dialog` (первый день, дни 1…30, сумма, способ оплаты, комментарий, живая проверка `/check` с конфликтующими бронями и «Свободно с 12:00 <дата>»); дни химчистки обведены в сетке (`days[].cleaning`); под сеткой — список химчисток месяца с отменой (подтверждение). Действия — только OWNER/MANAGER. `cashboxId` не передаётся — касса сотрудника. Проверено: `ng build`; в браузере против бэкенда не проверялось.
- **8.3 Mobile (billing-mobile) — готово 2026-11-09.** services/rental: типы, `useRentalCleanings`, `useCleaningCheck` (debounce 300 мс на экране), `useCreateCleaning` / `useCancelCleaning` (инвалидируют всё `rental` и кассы). `RentalItemScreen`: блок «Химчистка» (список, состояние, «+ Запланировать»), кнопка «В химчистку» рядом с «Забронировать» (OWNER/MANAGER), дни химчистки обведены в календаре. Экран `(products)/cleaning/[variantId]` (`CleaningNewScreen`) по макету `CleaningNew` без блока «Экземпляр»: календарь месяца (нет свободных / химчистка / выбрано), дни 1…30, «Свободно с 12:00 <дата>», конфликт — дни и брони (№код · клиент), расход, способ оплаты, комментарий, итог «Недоступен для брони». Нет своей открытой кассы → выбор кассы магазина. Отмена — `CancelCleaningSheet` (нажатие на запланированную строку); если открытой кассы нет — выбор кассы. `DRY_CLEANING` в кассе («Химчистка»), скрыта из ручной формы. Проверено: `tsc`, `expo export --platform web`; на устройстве не проверялось.
